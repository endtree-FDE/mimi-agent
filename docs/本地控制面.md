# 本地控制面

`mcp_server.py` 是给本机 MCP 客户端用的只读进程。主程序不 import 它，`agents/*.json` 里也没有它的开关。客户端不按下面的方式拉起它，这个进程就不存在。设计取舍见 [OpenMausBot对照与升级方案.md](OpenMausBot对照与升级方案.md)。

## 怎么启动

一条命令，一个位置参数：

```text
python mcp_server.py agents/<name>.json
```

`<name>.json` 与启动这一个机器人时用的是同一个文件。进程用 stdin/stdout 逐行收发 JSON-RPC，不监听端口，不连飞书，不发消息。

启动失败时退出码是 2，原因写在 stderr：没给配置路径、文件读不到、不是合法 JSON，或最外层不是对象。多出来的参数会被丢掉，只认第一个。整份配置会读进来做解析，交给工具的只有 `base_dir`（不写就用配置文件所在目录）、`redact_file`（默认 `redact.txt`）、`intake.enabled`、`intake.out_file`。profile、文档编号、模型接口不进工具输出；stderr 只打实例根和工具个数。

实例根和主程序同一把尺：`base_dir` 优先。`agents/example.json` 的 `base_dir` 是 `.`，工作目录因此必须是仓库根，读到的 `state/`、`intake/`、`redact.txt` 才是这一份实例的。

握手时客户端带了 `protocolVersion` 就原样回，没带则回 `2024-11-05`。服务名是 `mimi-agent-mcp`。认识的方法是 `initialize`、`ping`、`tools/list`、`tools/call`。没有 id 的通知不回。坏 JSON 行回 -32700，未知方法回 -32601，内部意外回 -32603，进程接着跑。

## 三个只读工具

`tools/list` 只列出下面三件，`listChanged` 为 false。调用清单外的名字（发送、审批、改配置、删除都算）会得到一张 `isError` 卡，进程不执行它。未知字段、缺必填、类型不对、越界，都在门口拒绝。

| 工具 | 参数 | 读什么 |
|---|---|---|
| `get_status` | 无。多写任何字段都会被拒。 | 版本（仓库根 `VERSION`，格式须是 `x.y.z`，否则空着）、心跳年龄（`state/heartbeat` 的 epoch 秒，读不到是 null）、接待桥是否打开、待审文件相对路径、段落总数、`seen_total`。心跳年龄大只说明该去看日志。`seen_total` 是账本里非空编号的条数（同一编号出现两次会算两次），表示拉到过多少；发没发由人决定，这里不另编一个剩余数。 |
| `list_leads` | 可选 `limit`（整数 1–50，默认 20）、`offset`（整数 0–10000，默认 0）。 | 待审合作意向，最新的在前。正文出进程前再过一遍脱敏和标记中和。 |
| `search_leads` | 必填 `query`（1–200 个字符，大小写不敏感）。schema 另接受可选 `limit`（1–100）；实现不使用这个数，单次最多返回 100 段。 | 标题或正文里含关键词的段，最新的在前。同样先脱敏再出去。 |

待审文件超过 1MB，或路径被判定为绝对路径、盘符、`..`，工具拒绝读并回一张错误卡。文件不存在时列表是空的，进程不退出。

意向正文出进程前都过 `guard.redact` 和 `guard.neutralize`。工具输出不包含配置里的密钥字段。密钥本来就不该写进 `agents/*.json` 或 `.cursor/mcp.json`。

## 只读边界

这个进程不能审批、发送、改配置、删除文件，清单里也没有写入类工具。飞书上的写操作仍只走主程序的三道白名单和发起人确认。确认不能关。双人复核留在主程序的 `write.decision_gate` 里；控制面不参与，这一页保持该开关关闭。

## 项目级 mcp.json 示例

Cursor 使用仓库根的 `.cursor/mcp.json`。这份文件只对当前仓库生效，工作目录和配置路径都绑在这一个实例上。

仓库不提交填好的那份文件。`<name>` 和本机 Python 路径每人不同，提交进去会让别人的客户端拉起一个对不上的进程。下面是抄到本机 `<仓库根>/.cursor/mcp.json` 的样子。

```json
{
  "mcpServers": {
    "mimi-agent": {
      "command": "python",
      "args": ["mcp_server.py", "agents/<name>.json"],
      "cwd": "."
    }
  }
}
```

- `command` 的 `python` 是占位。换成你在这个仓库里跑测试用的那个 Python 3.12 解释器。Cursor 拉起子进程时不一定带上终端里的 PATH，对不上时改成该解释器的绝对路径。个人目录留在本机，不写进仓库。
- `args` 第一项是脚本名，第二项是实例配置，都相对 `cwd`。`<name>` 换成这份机器人的配置文件名。占位示例可以写 `agents/example.json`。
- `cwd` 是仓库根，和 `mcp_server.py` 同一层。项目级文件放在仓库根时，`"."` 就是这一层。客户端若把相对目录解析到别处，改成仓库根的绝对路径。
- 示例里没有 `env`。不要写入 App Secret、模型密钥、`TAVILY_API_KEY` 或任何环境变量。控制面不需要它们。密钥留在原来的位置，由主程序自己读。

## 和示例配置里的只读配套

`agents/example.json` 的 `tools` 里另有四项只读工具，全部 `"enabled": false`：

| 键 | 给谁用 | 做什么 |
|---|---|---|
| `evidencegate_check` | 主程序 | 内容可信度，三路由 |
| `decision_gate_check` | 主程序 | 按证据状态、动作等级、可逆性算路由，只算不执行 |
| `evidence_replay_check` | 主程序 | 核对回放归档的标签、哈希与缺口登记 |
| `receipt_verify` | 主程序 | 离线核验 Matrix 回执导出，结果只证明内部一致 |

这四项出现在主程序的工具说明里，不出现在 `mcp_server.py` 的清单里。逐项怎么填见 [agents/CONFIG.md](../agents/CONFIG.md) 的「工具 tools」。

同一份示例里 `write.decision_gate.enabled` 是 `false`，声明的等级是 L2。保持这样。这一页不打开写工具，也不改等级。
